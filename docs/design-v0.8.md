# 第一卷 · 设计哲学与内核原则

## 定义

一个**时间线驱动、内容与呈现彻底分离、主题可换肤**的内容播放与创作引擎。佛教梵呗是第一个垂直应用,引擎核心对领域无知,可横向扩展到诗词、蒙学、语言学习、有声书、冥想、教学等。

创作物是**活的数据**;视频、字幕、自包含 HTML、可打印静帧都只是导出格式——把活数据在某一刻"烤死"的输出之一,而非创作形态本身。

> **战略身份**:表面在做"梵呗内容引擎",底座实为"结构化、可复现、多形态输出、时间驱动的**东方文本呈现标准**"。竖排、注音、逐字点亮、章节配色、多注音体系、传统记谱,是所有 CJK 古典文本共享的呈现语言,数字世界至今无标准。佛教是滩头阵地,不是天花板。每个决策多问一句:**"这只对佛教成立,还是对所有东方文本成立?"**
> **姿态纪律**:标准是做出三个漂亮垂直场景之后**被追认**的,不是先宣告的。保持克制,先把窄场景做到极致。

## 第一原则(最高准则)

**高效、尽量功能丰富、有趣、轻量化、能真实落地——以"能落地"为最高准则。** 任何让系统沦为"缝合怪"的设计一律否决。

## 三条优雅范式(设计骨架,类比 Blender 数据哲学)

1. **统一基元(everything is a Track)**:不区分内容与音频的主从,万物归一种平等基元——轨道。概念越少,组合越多。
2. **非破坏性 + 数据与呈现分离**:内容是可编辑的结构化数据,不是烤死的成品;属性是"挂"上去的描述,不污染内容。
3. **共享协调空间,而非两两绑定**:轨道之间不互相绑定,只各自锚定到唯一共享时间线。复杂度 O(N) 而非 O(N²)。

**刻意不学的东西(铁律)**:借鉴 Blender 的"统一对象 + 非破坏性 + 共享空间",但**坚决不要"任意节点连线"**。轨道之间永远只通过时间线这唯一中介发生关系,**绝不互相直连、互相触发**。这是防止系统膨胀失控的根本。

## 内核原则(不可动摇的地基)

1. **内容即数据**:任何把领域逻辑嵌入引擎的机制(状态机、条件分支)一律禁止。领域知识全部活在模板与数据里。
2. **schema 先于工具**:框架/画布/对齐工具可晚定、可替换;数据契约一旦写下即地基。
3. **零领域硬编码**:引擎不认识"本/章/句/字""遍数""會"等任何领域词;层级名由模板按深度赋予。
4. **反猜语义**:引擎不替作者补内容、不猜意图。缺定义 = 报错,不是运行期兜底。
5. **现补几近免费,晚补全量重构**:与覆盖链/命令流同源的能力应尽早补齐。
6. **人写的 ≠ 机器存的 ≠ 人看的**:输入层(极简骨架)、存储层(parser 编译出的严格结构)、呈现层三者分离。简单是表面的,强大是底层的。
7. **一份数据,多个消费者**(v0.8 强化):作者、观众、导出器、导航器都只是同一份活数据的不同消费者;任何新需求,先问"能否让已建成的骨架多服务一个消费者",而非新增机制。

## 选型硬约束(许可证)

在保证先进、高效、轻量的前提下,**优先选用 MIT(或同等宽松、可商用)的开源技术;商业付费服务仅在"极高性价比"时考虑,默认不用。**

- **干净可商用**:MIT / Apache-2.0 / BSD / ISC。
- **带传染或商用限制(慎用/回避)**:AGPL / SSPL / **BUSL**(Remotion 即属此类)。

每个选型须标注许可证。

## 已压测通过的三大危险决策(信心来源)

- **锚点统一**:节拍对齐、时间戳对齐、打点对齐三者产物同构,锚点唯一真相是 `time`,对齐方式只是"锚点生成器"差别,下游零分叉。
- **多区间激活态**:`unit → [{t0,t1}]` 把拖腔/轮唱/双语统一为"区间命中"单一判定,逐轨独立计算,O(bindings) 线性。
- **视觉覆盖链**:令牌/槽位/精修/观众意图是声明式覆盖而非重写,换主题自动联动、删覆盖自动回落、属性互不污染。

# 第二卷 · 五维内核与核心抽象

## 五维内核

任何场景的内容,本质都是一棵**带时间、带标注、可重复、可配置的节点树**,由五个**正交、可组合、各自可省略**的维度构成:

| 维度 | 含义 | 抽象不变量 |
|---|---|---|
| **1. 层级 Hierarchy** | 内容如何嵌套分组 | 任意深度递归树;层级名(本/章/句/组/步骤)是标签属性,绝不进语法 |
| **2. 时序 Timing** | 节点如何与时间关联 | 每节点可选携带时间描述:时间戳 / 时长 / 空(纯顺序) |
| **3. 标注 Annotation** | 给节点附加平行信息 | 任意节点可挂零到多条**具名平行轨道**(拼音/注音/IPA/翻译/排版角色…) |
| **4. 重复 Count & Loop** | 重复与计数 | 任意节点可声明重复 N 次;当前第几次由激活态反推,非可写状态(§2.4) |
| **5. 配置 Presentation** | 默认如何显示 | 任意节点可携带配置覆盖;子继承父、可局部覆盖 |

**铁律(多场景压测逼出)**:

- 语法层绝不出现领域词(没有 `遍数:`/`章节:`,只有抽象的重复修饰/层级符号/标注轨道)。
- 五维正交可组合,每维可省略(最简单内容用最简单写法)。
- 层级深度不固定(数据上无限递归,用户面前的有限层级由模板赋予)。

## 三个核心概念

**轨道 Track、时间线 Timeline、锚点 Anchor**——整个数据模型只有这三个核心概念。

```
作品 (Work)
├─ 时间线 (Timeline)        ← 唯一共享协调空间;一组独立的锚点 (Anchors)
└─ 轨道集合 (Tracks)        ← 一组地位平等的轨道
   ├─ 文本轨 (Text Track)   ← 内部是一棵五维节点树
   ├─ 音频轨 (Audio Track)  ← 波形 + 可选分段
   ├─ 标注轨 (Annotation)   ← 拼音/翻译/和弦/排版角色/位置…
   └─ …(任意多条,类型不同,地位平等)
```

- **锚点为第一公民**:锚点是时间线上的独立对象,不被内容或音频任何一方拥有,双方都只"引用"其 id。同时支持"音频优先"与"内容优先"两种工作流。
- **轨道只锚定时间线,不互连**:换音频不动文本;文本、音频、对齐三者各自独立可替换。
- **树与时间线正交**:树管一条内容轨**内部**的层级(本→章→句→字);时间线管多条轨道**之间**的并行对齐。
- **时间线是可选协调层**:食谱、念珠计数、纯阅读等"进度/计数驱动"场景无需时间线,可**退化为纯树**。

## 激活态(Active State)— 一等概念

在任意时刻 t,引擎对每条轨道**独立计算"哪些单元处于激活态"**(可零个、一个、多个)。这是逐字高亮、双语同步、和声显示、当前句方框的**统一底层机制**(计算契约见 §3.5)。

## 挂件 = 激活态的订阅者(纯函数)

**挂件 = 纯函数**:`f(某条/某几条轨道在时刻 t 的激活态 + 配置) → 画面`。无状态、不碰音频、不碰其他挂件。新增一个挂件成本恒定,复杂度不随功能数累积——这是"轻量化"的工程定义。挂件正式契约见 §7.5,清单见第七卷。

## 主时钟契约(v0.8 新增,§0)

**t 的唯一真相源必须单一且显式声明,禁止多时钟。**

- 有音频轨的作品:`AudioContext.currentTime` 为唯一 master clock;`t = audioContext.currentTime - trackOffset`。`requestAnimationFrame` 仅是**采样时机**,不产生时间。
- 无音频轨的作品(纯阅读/冥想/念珠):退化为 `performance.now()` 驱动的软时钟。
- 暂停 = 冻结 t;seek = 直接设定 t;变速 = t 轴线性缩放(§12.1)。三者语义随主时钟契约免费获得。
- **理由**:rAF 时间戳会漂移、后台标签会节流、音频解码有延迟。锁死单一时钟源,消除整类音画不同步 bug。

## "多对多"问题的消解

| 场景 | 在统一模型下的表达 |
|---|---|
| 多音源切换(乐器/女声/男声) | 多条音频轨,各锚定同一时间线;切换=`playback.activeAudioTrack`(§1.6) |
| 轮唱/多声部 | 多条文本轨,内容相同、锚点错峰 |
| 中英双语对照 | 两条文本轨,共享锚点,同时激活 |
| 法会串多部经 | 时间线上排开的多个不重叠区段 |

# 第三卷 · 数据契约(schema)

## 1. 顶层文件结构

一个**作品(Work)**是一份可序列化 JSON。人写的极简骨架经 parser 编译进此结构。

```json
{
  "schemaVersion": "0.8",
  "meta": { "title": "...", "domain": "buddhist-chant", "lang": ["zh"] },
  "timeline": { "anchorGroups": [ /* §3 */ ] },
  "tracks": [ /* §2 轨道,地位平等 */ ],
  "playback": { "activeAudioTrack": "track-audio-female" },  // §1.6
  "visual": {
    "templateRef": { "id": "...", "version": "..." },   // §18 pin 死
    "overrides": { /* §5.3 单元精修 */ }
  }
}
```

- `domain` 只是元数据标签,**引擎不据此分支**。拆分器、层级名映射全由模板消费。
- `timeline` 整体可缺省 → 退化为纯树(食谱/念珠场景)。
- `visual.templateRef` 为 `{id, version}` 二元组,锁定具体模板版本(§18)。
- `playback` 存作者预设的播放态(如默认音源);观众端瞬态覆盖不写入此处(§12)。

### 1.6 playback 字段(v0.8 新增)

```json
"playback": {
  "activeAudioTrack": "track-audio-female",  // 多音源时的默认播放轨
  "defaultRate": 1.0
}
```

- 承载**作者预设**的播放态,是作品数据的一部分,进 undo。
- 多音源"切哪条"存于此;导出适配器据 §21 决定该开关"焊死"(视频)还是"保活"(HTML,观众可切)。这是"开关正交性"铁律的落点。

## 2. 轨道 Track 统一 schema

万物归轨道。所有轨道共享同一外壳,靠 `type` 区分内部载荷。

```json
{
  "id": "track-main",
  "type": "text | audio | annotation",   // 引擎认识的物理类型
  "role": "main | pronunciation | translation | layout | ...",  // 纯语义标签
  "anchorGroupRef": "ag-vocal",           // §3.4,可省略,缺省指向首组
  "content": { /* 因 type 而异 */ }
}
```

- `type` 决定如何渲染/计算激活态;`role` 是纯标签,引擎不分支,挂件靠它筛选订阅哪条轨。
- `anchorGroupRef`(v0.8 补齐):声明本轨 binding 在哪套锚点组内解析(§3.4)。省略即首组。
- 新增一种注音(IPA)= 新增一条 `type:annotation, role:ipa` 轨,引擎无需改动。

### 2.1 文本轨内部:五维节点树

```json
{
  "id": "u-0042",
  "block": { "kind": "text", "value": "南無" },   // §4
  "children": [ /* 递归,任意深度 */ ],
  "timing":  { "bindings": [ /* §3.3 区间引用,可省略 */ ] },
  "repeat":  { "count": 7 },                       // 重复维,可省略;无 index(§2.4)
  "config":  { /* 配置覆盖,子继承父,可省略 */ }
}
```

- 层级名不进 schema,节点只有 `children` 表达嵌套深度。
- 五维全部可省略:最简内容只有 `block`,其余字段缺省即关闭该维。

### 2.2 连读单元的边界归属

拆分器产出的"连读块"就是一个普通节点。`般若` 不拆 = 一个 `block.value:"般若"` 的叶节点;注音/激活态挂在该节点上,而非两个字符上。**最终单元边界即节点边界**,无独立字符层。

### 2.3 分单元三层策略

- **第一层(引擎)**:只认识抽象"单元",不关心怎么拆。
- **第二层(模板)**:提供该领域默认拆分器——中文=按字符拆 + 连读词典;语言学习=按词;咒语=按音节;健身=数字+单位保整体。
- **第三层(用户)**:在默认结果上手动合并/拆分。

**第一阶段拆分器定案**:档位 2——内置小型佛教常用连读词典(纯 JSON,MIT 无依赖,可随用扩充)。词典条目带 `source` 字段(`builtin | user`),为社区共享词典留门。不采用通用分词库(对古汉语/音译词易错)。

### 2.4 repeat 维定案(v0.8 关键修订):解析期展开,非运行期循环

**问题**:v0.7 中 `repeat.count` 与 `timing.bindings` 同时存在时语义未定义,且 `repeat.index` 作为可写状态会引入 f(t) 之外的第二时钟,违反纯函数铁律。

**定案**:`repeat` 是**压缩表示**,由解析期"重复展开器"(与 `anchorsFromBeats` 同族的锚点/实例生成器)展开为时间线上的 N 个实例区间。

- 展开后,f(t) **零感知重复的存在**——它只看到 N 个平铺的实例。
- "当前第几遍"由激活态**反推**(当前命中第几个实例区间),不是存储字段。故 §2.1 移除 `repeat.index`。
- undo/快照无需理解重复,只见展开前的压缩数据。
- **无时间线场景**(念珠、纯计数)的"当前遍数"不走展开,归 §23 的 `increment` 基元管理——两条路径在 schema 上显式分家:**有时序 → 展开;无时序 → increment。**

## 3. 时间线与锚点 schema

### 3.1 锚点:唯一真相是 time

```json
{
  "id": "a12",
  "time": 4.0,                                    // 秒,唯一本质字段
  "origin": "beat | manual | forced-align | tap"  // 仅元数据,引擎不据此分支
}
```

- 锚点是时间线上的独立对象(第一公民),不被内容或音频拥有,双方都只引用其 `id`。
- `origin` 仅供编辑器 UI 区分显示;激活态计算完全不看 origin。

### 3.2 三种锚点生成器(v0.8 新增第三种)

对齐方式只是"锚点生成器"的差别,产物同构,下游零分叉:

**① 节拍对齐**(匀速唱诵主力):
```
anchorsFromBeats({ bpm, beatsPerUnit, startTime, count }) → [Anchor(origin:"beat")]
  time_i = startTime + i × (60 / bpm) × beatsPerUnit
```
换语速 = 改 BPM 重新生成 `beat` 锚点(`manual` 锚点不动)。

**② 时间戳对齐**(自由节奏):直接给 `time`,`origin:"manual"`。

**③ 打点对齐 tap-to-align**(v0.8 新增,拖腔/自由节奏主力):
```
播放音频,作者跟随诵读逐单元敲击 → 每次敲击生成 Anchor(origin:"tap")
  顺次绑定到下一未对齐单元
```
- 实现成本 ≈ 一个键盘/触摸监听,却把"逐字对齐"从不可忍受变成一遍过。
- **契合领域现实**:作者本人最懂拖腔板眼,比 AI 强制对齐(二阶段、有依赖)更早可用、更准。
- 完美复用"对齐方式=锚点生成器"抽象,零架构成本。**列入第一阶段。**

三种生成器写入时间线后无区别。

### 3.3 对齐:内容引用时间区间(支持多区间可重叠)

```json
"timing": {
  "bindings": [
    { "from": "a3", "to": "a4" },
    { "from": "a5", "to": "a6" }   // 同一单元可绑多段、可重叠
  ]
}
```

- 区间用**锚点 id 对**表达,不写死秒数 → 锚点时间一改,所有引用自动跟随。
- 句级绑定 + 字级插值:句节点带 `bindings`,子字节点不带 → 引擎在句区间内按子节点数均匀插值;需更细则给字节点补 `bindings`。
- **插值精度纪律**(v0.8):均匀插值是**草稿精度**。汉语唱诵字时值极不均匀(拖腔、板眼),精修靠 §3.2 的打点对齐或二阶段强制对齐补密集锚点,不靠均匀假设。编辑器须明示"当前为均匀插值草稿"。

### 3.4 多套锚点分组

```json
"timeline": {
  "anchorGroups": [
    { "id": "ag-vocal", "anchors": [ /* ... */ ] },
    { "id": "ag-drum",  "anchors": [ /* ... */ ] }
  ]
}
```

服务节奏不同的多条音轨。`binding.from/to` 在其轨 `anchorGroupRef`(§2)指定的组内解析;省略即首组。

### 3.5 激活态计算

逐轨独立。给定时刻 t,`unit` 激活 ⟺ 其任一 binding 区间命中 t(`t ≥ t0 && t < t1`)。可零/一/多个单元同时激活。逐字高亮、双语同步、和声显示、当前句方框全部是这一个函数的应用。变速下 t 已按 §12.1 缩放,激活态计算无感。

## 4. 可渲染块 block schema

### 4.1 两把正交分类尺子

- **尺子 A｜时间性**:若自带时间,必须可表达为作品 `t` 的纯函数;否则超边界,不予支持。
- **尺子 B｜内部可寻址性**:内部子元素是否需单独进入激活态/精修系统。需要 → 破壳成节点树 + 渲染插件;不需要 → 黑盒块即可。

### 4.2 `block.kind` 定案

| kind | 定位 | 优先级 |
|---|---|---|
| `text` | 黑盒静态块 | 已实现 |
| `image` | 黑盒静态块;动态背景主力(§14.4) | 已实现 |
| `formula` | 黑盒块(整体激活);逐项讲解时 `opaque:false` 破壳 | 低 |
| `media` | 黑盒块,时间性受 §14.3 约束 | 押后 |
| `note` | 破壳单元 + 渲染插件(五线谱等) | 插件赛道 |

**移出 block 名单:**

- `score` = `note` 节点树 + 五线谱渲染插件。
- `chart` = 破壳节点 + 声明式 grammar 库。
- 留白/呼吸/磬声间隙 = 空 block(占时间、不渲染)。
- 装饰纹样(莲花/光晕/边框/背景图)= 视觉模板层(§5.5),非内容 block。

> 原则:破壳类一律集成声明式库,不自研渲染。

### 4.3 `opaque` 字段

- **类型** boolean，**默认** `false`
- **语义**:声明引擎能否寻址该 block 内部。`true`=黑盒(整体激活),`false`=可寻址(子元素入激活态系统)。
- 所有 block 共用此开关;同一 `kind` 按 `opaque` 取不同命运。
- 默认 `false`:活数据是常态、零配置;黑盒是主动放弃内部所有权的例外,须显式声明。
- 前瞻:布尔够用;未来若需"部分可寻址",非破坏性升级为 enum。

```json
{ "block": { "kind": "text",    "value": "南無" } }               // 默认可寻址
{ "block": { "kind": "formula", "opaque": true, "value": "…" } }  // 整体激活
{ "block": { "kind": "formula", "value": "…" } }                  // 逐项破壳
```

## 5. 视觉模板 schema(三层解析链 + 观众端第四层)

视觉模板是**独立文件**,结构为 `{ tokens, slots }`。作品只持有 `visual.overrides`。

> **核心洞察**:视觉的丰富度,该用"层次的深度"提供,不该用"参数的数量"提供。用户在自己想介入的那一层操作,其余层自动有合理默认。约 90% 用户只用第一层。

### 5.1 第一层:令牌 tokens(主题 = 一组取值)

```json
"tokens": {
  "color.fg":     { "light": "#1a1a1a", "dark": "#e8e6e0", "sepia": "#3a2f1a" },
  "color.bg":     { "light": "#faf8f2", "dark": "#1a1714", "sepia": "#f4ecd8" },
  "color.accent": { "light": "#b8860b", "dark": "#d4a843", "sepia": "#a8741a" },
  "color.group.G1": { "light": "#6b3fa0", "dark": "#b088e0", "sepia": "#7a4a2a" },
  "type.scale":   { "base": 16, "main": 28, "ruby": 11 },
  "motion.easing":{ "default": "ease-in-out", "solemn": "cubic-bezier(.4,0,.2,1)" },
  "bg.image":     { "light": "assets/bg-light.webp", "dark": "assets/bg-dark.webp" },
  "bg.mask":      { "light": 0.0, "dark": 0.3 }
}
```

- 挂件与排版**只引用令牌名**(`"$color.accent"`),绝不写死色值。
- "主题/换肤" = 切换令牌取值分支(`light`/`dark`/`sepia`/自定义),引用处全部联动 → 永不出现"改了背景字看不清"的崩坏。这是换肤丝滑与鲁棒性的共同来源。
- 易背诵分组色(`color.group.*`)也是令牌分支:作者打语义分组(§6),色值由主题派生,换肤联动。

### 5.2 第二层:槽位 slots(网格)

采用网格槽位(类 CSS Grid)。第一阶段只开放几套预设布局,底层即网格引擎。

```json
"slots": {
  "grid": { "areas": ["title", "main", "ruby", "count", "chapter", "minimap"] },
  "title":   { "place": "1 / 1 / 2 / -1", "size": "$type.base" },
  "count":   { "place": "1 / -3 / 2 / -1" },
  "chapter": { "place": "2 / 1 / 3 / -1", "size": "$type.base" },
  "main":    { "place": "3 / 1 / 4 / 2",  "size": "$type.main", "writingMode": "vertical-rl" },
  "ruby":    { "position": "right", "size": "$type.ruby" },
  "minimap": { "place": "4 / 1 / 5 / -1" }
}
```

- 槽位是语义区域(标题/主经文/注音/遍数/章节/缩略带);用户决定每个槽位放哪个挂件,非像素自由摆放。
- 注音位置(上/下/左/右)是槽位属性,不写死。竖排下 `ruby.position:"right"` 对应本领域惯例。
- 槽位内属性同样可引用令牌 → 换主题联动。
- **自由度取舍**:底层网格引擎(网格内自由放置缩放,自动对齐网格线),第一阶段先只开放几套预设布局,成熟后再开放网格自由编辑。

### 5.3 第三层:精修 overrides(挂作品,不挂模板)

存于 `visual.overrides`,key 为节点 id:

```json
"visual": {
  "templateRef": { "id": "theme-classic", "version": "1.0.0" },
  "overrides": {
    "u-0042": { "color": "$color.accent", "size": 36 }
  }
}
```

- 是"例外"非"常态",永远**覆盖**而非**重写**;删掉 key 即回默认。
- 只覆盖列出的属性,其余继续从槽位/令牌继承。每处精修可隔离可回退。

### 5.4 解析链(渲染时查表顺序)

```
令牌默认 → 槽位局部 → 单元精修 → 〔观众意图〕   (后者覆盖前者同名键)
   ↑ 再对结果做一次 $token 解引用(代入当前主题分支取值)
```

- 前三层是作者态,进作品数据/undo。
- 第四层「观众意图」(§12)是**瞬态覆盖**,存本地/URL,不写回作品、不进 undo,可一键复位。
- 声明式、纯查表、零状态。

### 5.5 背景图与装饰:令牌化资源(v0.8 新增)

装饰性背景**归视觉模板层,不进内容 block**(§4.2)。三条纪律:

1. **背景图是令牌分支,不是固定图片**:`bg.image` 按主题(light/dark/sepia)取不同底图,随 `theme` 令牌联动切换。永不出现"暗色主题下浅底图糊字"。
2. **蒙版层保可读性**:底图上盖一层可令牌化透明度(`bg.mask`)的纯色蒙版,压低对比、护住正文。暗色主题蒙版更重。
3. **只存引用,导出内联**:源数据只存 `src`(§14.2);自包含 HTML 导出时由适配器按体积预算内联/转 WebP 降档(§14.5)。源数据干净,导出产物自包含,两件事。

- 动态背景(缓慢 Ken Burns / 淡入淡出)= `image` block + 声明式运动(§14.4),不碰 media 二进制。
- 内容性图片(某句配佛像、跟诵切换)= 内容轨里的 `image` block,与经文平级,能进激活态。

## 6. 排版轨 schema(易背诵版)

排版轨是特殊标注轨(`type:annotation, role:layout`),携"单元的版面视觉角色"。**易背诵版**即其表现。

```json
{
  "id": "track-layout-mnemonic",
  "type": "annotation",
  "role": "layout",
  "content": {
    "tags": {
      "u-0042": { "group": "G1", "baseline": "ruler-2" },
      "u-0051": { "group": "G1", "baseline": "ruler-2" }
    }
  }
}
```

- `group`:颜色分组标识(同组同色);配色由视觉模板按分组从 `color.group.*` 令牌派生,排版轨本身不写色值。
- `baseline`:对齐基准标识,形成记忆锚点。
- 引擎不知分组语义规则:规则由可插拔排版插件产出 tag,引擎只负责"单元带 layout tag 就照渲染"。这张 `tags` 表就是插件接口。
- **双重身份**(v0.8):同一份分组数据,作者端是排版(输出物),观众端是遮字自测的遮罩地图(§12.4)。数据复用到极致。

> 现机制支持"同类句同色 + 对齐基准线"(易背诵版主流形态)。不支持"打断自然顺序的二维记忆网格重排",如需属未来扩展。

## 7. easing、转场与挂件契约

### 7.1 easing

属性随时间过渡的曲线,是令牌枚举(`motion.easing.*`),可在令牌/槽位/精修三层继承覆盖。

### 7.2 转场 transition(v0.8 扩展:enter 枚举 + delay 编排)

转场是激活态切换或视图进入/退出瞬间的过渡,声明在视觉模板顶层或槽位上,非挂件内部动画。`on` 为**封闭枚举**(防滑向状态机):

| on 取值 | 触发时机 | 用例 |
|---|---|---|
| `enter` | 作品/槽位**首次进入视图** | 标题落下、经文浮现、导航升起 |
| `activeChange` | 激活态切换 | 当前句推进高亮 |
| `exit` | 退场(章节/分段切换) | 会与会之间过渡 |

三值封死,不开放任意事件。

```json
"transition": {
  "title":   { "on": "enter", "type": "slide", "from": "top",    "duration": 0.8, "delay": 0.0, "easing": "$motion.easing.solemn" },
  "main":    { "on": "enter", "type": "fade",                    "duration": 1.2, "delay": 0.3, "easing": "$motion.easing.default" },
  "minimap": { "on": "enter", "type": "slide", "from": "bottom", "duration": 0.8, "delay": 0.5, "easing": "$motion.easing.default" },
  "main.active": { "on": "activeChange", "type": "wipe", "direction": "rtl", "easing": "$motion.easing.default" }
}
```

- **key 到槽位**:不同槽位可有不同转场(v0.8 修订,v0.7 仅顶层单条)。
- **`delay` 做编排层次**:标题先落、经文再浮、导航最后升,靠 delay 值编排,无需时间轴。
- **easing 引用令牌**:换主题连同动效性格一起换(庄严/活泼)。
- 底层落地为 CSS transition/keyframes(浏览器原生、GPU 加速、零依赖);作者写声明,不写 CSS。

**`enter` 一次性纪律(关键,防误实现)**:`enter` 转场绑定"首次进入视图"事件,是**一次性**的,**不随播放头 seek 重放**。入场编排的时间原点是"作品载入时刻",与音频时间轴 t 是两个原点;不得混用,否则用户拖到第 5 分钟标题会又落一次。

- **边界**:入场/退场/激活推进覆盖内容动效 99% 需求。自由轨迹动画(花瓣沿曲线绕场)需通用关键帧,本系统**不做**,引导至 §13.2 Canvas 局部特效层旁挂,绝不为其往内核塞时间轴。

### 7.5 挂件契约(v0.8 正式化,原为附录空白)

挂件是订阅激活态的纯函数,契约极薄:

```
Widget {
  subscribe: [trackRole]                        // 声明订阅哪些轨(靠 role 筛)
  render(activeState, tokens, geometry) → 槽位内容  // 纯函数,无状态
}
```

- 输入:所订阅轨在当前 t 的激活态 + 当前主题令牌表 + 字级几何表(§12.2)。
- 输出:填入所在槽位的声明式内容。
- 禁止:持有内部状态、读音频、读其他挂件、读真实 DOM。
- **变体不做成独立挂件,用配置区分**(订阅同一类数据者即同一挂件的变体),避免挂件库爆炸。
- 新增挂件成本恒定,复杂度不随功能数累积。

### 7.6 效果器契约(v0.8 正式化,与挂件同为原空白)

效果器是作用于单元/槽位的声明式视觉效果(如 Ken Burns、辉光、淡入):

```
Effect {
  target: unitId | slotId
  kind: "kenburns | glow | fade | ..."   // 封闭枚举
  params: { ... }                          // 纯数据
  → 产出 t 的纯函数,叠加进帧状态
}
```

- §14.4 的动态背景 Ken Burns 依赖此契约。效果器不引入时钟,只是帧状态的纯函数叠加层。


## 8. 纯文本骨架符号

**前缀井号累加表示绝对层级 + 借形不借义的 Markdown 极简方言**。

| 写法 | 含义 |
|---|---|
| `#` 行 | 第一层节点(井号数 = 绝对层级深度) |
| `##` / `###` 行 | 第二 / 第三层…… |
| 普通行 | 最小内容单元(叶节点) |
| 空行 | 分段(同级视觉分隔,不产生层级) |
| `×7`(行尾) | 重复修饰:该节点重复 7 次(**非** `遍数:`) |

- 只借 Markdown 符号直觉,不继承语义:不支持链接/粗体/表格。
- 层级 → 领域名映射、数井号提示,全由模板 + 编辑器 UI 消化;语法层零领域词。
- 注音**不写进骨架**,通过界面挂到对应节点,存为 `annotation` 轨。骨架永远只有干净正文。
- 骨架 → JSON 由自写轻量 parser(纯 TS)编译;人和 AI 走同一管道。
- **往返性定案(v0.8)**:骨架是**导入格式,不是存储格式,不承诺无损往返**。编辑器内合并连读、挂注音、加精修后,存储层(严格 JSON)成为唯一真相;骨架只用于快速录入正文,不承担回存职责。

# 第四卷 · 模板体系

## 16. 模板继承

### 16.1 定案:单链继承,拒绝多重继承

模板继承为**单亲链**(`extends` 指向 0 或 1 个父模板)。多重继承会引入冲突消解规则——本质是隐藏在解析层的条件分支,违反无分支原则。单链沿链自 root 向 child,**离 child 越近的 override 越晚生效、越优先**,线性、无需判优先级。

> 反面参照:CSS specificity——为解多来源冲突长成没人能心算的隐性优先级引擎。本项目拒绝走这条路。

### 16.2 继承 = 三层链的递归应用

1. 父模板先完整 resolve,产出一份 **flattened token 表**(已应用父自身全部 override);
2. child 的 override 链以这份 flattened 表为起点,再走一遍同一套三层算法。

schema 层仅需在模板根新增一个可选 `extends` 字段,零新增求值分支。

```json
{
  "template_id": "sutra.gold",
  "version": "1.2.0",
  "extends": { "id": "sutra.base", "version": "2.0.0" },
  "overrides": { "slot.title.fill": "token.gold.500" }
}
```

### 16.3 链深与环检测

- 继承链在**解析期一次性摊平**,运行期 f(t) 永不遍历继承链。
- 环检测为纯静态图检查(DFS 查环),属 §22 验证期职责。
- 不设人为链深上限;环检测已足够防病态。

## 17. 模板组合

### 17.1 定案:组合与继承正交并存

继承解决「A 是 B 的特化」(override 语义);组合解决「A 同时装配 X 和 Y 两个互不相关的预设片段」(拼接语义)。两套独立机制,可同时使用,不得相互模拟。

### 17.2 fragment:可复用的 token 子集

- **fragment** = 一束具名 token/slot 定义,自身不可独立渲染,只作被装配件。
- 模板经 `compose: [fragmentRef, …]` 声明装配。
- **合并规则:仅允许不相交合并(disjoint merge)**。两个 fragment 触碰同一 token = 作者错误,由 §22 验证期**静态报错**。作者需要覆盖时,应显式改用继承(§16)。

```json
{
  "template_id": "sutra.gold.vertical",
  "version": "1.0.0",
  "extends": { "id": "sutra.base", "version": "2.0.0" },
  "compose": [
    { "id": "theme.gold",      "version": "1.0.0" },
    { "id": "layout.vertical", "version": "1.1.0" }
  ]
}
```

### 17.3 组合与继承的求值顺序

见 §19:**先组合,后继承,再 resolve**。顺序固定、不可配置。

## 18. 模板版本

### 18.1 定案:引用 pin 死,拒绝 live-follow

所有跨实体的模板引用均为 **`{ id, version }` 二元组**,锁定具体版本;绝不按名跟随最新。自包含 HTML 导出应是确定性产物:同一份作品数据永远渲染出同一结果。升级是作者主动操作,引擎永不自动迁移。

### 18.2 版本语义:SemVer 兼容契约

| 变更 | 版本位 | 含义 |
|---|---|---|
| 新增可选 token/slot,不改既有 | minor | 向后兼容,升级安全 |
| 改既有 token 默认值 / slot 结构 | major | 破坏性,渲染会变,须作者确认 |
| 修错别字 / 注释 / 无渲染影响 | patch | 视觉无感 |

工具层**可**提示"有新版本可用",但决策权 100% 在作者。

> **二阶段工具增强(记一笔)**:SemVer 靠作者自律不可靠;工具层可加"渲染快照 diff"(旧版 vs 新版各渲一帧像素比对)自动判定 major/minor,防止模板生态污染。

### 18.3 未定案·留待工具层

- 模板**存储/分发**形态(本地文件 / 社区 registry)属第二阶段,不锁。
- 版本冲突:**同一解析上下文内,同一 fragment 只允许一个版本**,多版本共存是验证期硬错误。

## 19. 解析总管线

### 19.1 从「模板引用」到「flattened token 表」的确定性管线

```
作品.template_ref { id, version }
        │
        ▼
  [1] 版本解析      按 {id,version} 取定具体模板(§18)
        │
        ▼
  [2] compose      并入全部 fragment(disjoint merge,§17)
        │
        ▼
  [3] inherit      沿 extends 单链自 root→child 摊平 override(§16)
        │
        ▼
  [4] resolve      走 token→slot→override 三层链(§5)
        │
        ▼
  flattened token 表  →  供 §12 f(t) 与字级几何表消费
```

- **全程静态、无副作用、确定性**:相同输入恒产相同 flattened 表——§18 可复现性的机制保证,也是 §20 undo/redo 快照可信的前提。
- 管线跑在解析期,不入 f(t) 运行循环。运行期只见成品 token 表。
- 观众意图(§12)是运行期叠在 flattened 表之上的第四层,不进此静态管线。

### 19.2 顺序为何不可配置

compose→inherit→resolve 固定顺序 + 各步骤内禁止相交冲突,共同保证整条管线无一处需要运行期判优先级。任何"让作者配置管线顺序"的设计都等于给引擎注入分支。

# 第五卷 · 渲染与导出

## 12. 渲染架构

### 12.1 f(t) → 帧状态 → 多 renderer

f(t) 求值器**不直接操作画面**,只产出声明式**帧状态**:每个 unit 此刻的填充/位置/透明度/激活态。实时预览、Canvas 特效层、Revideo 导出、字幕导出均为帧状态的 renderer,共享同一 f(t) 核心。实时预览只是第一个适配器,非"主渲染"。

- **变速统一在此层**:`t = (masterClock - offset) × rate`(§0 主时钟 + §12 采样)。f(t) 收到已缩放的 t,内部零感知变速。

### 12.2 两份共享契约

- **帧状态(动态)**:`f(作品, t) → [{ id, fill, opacity, active, … }]`,纯函数、无副作用。
- **字级几何表(静态,t 无关)**:`{ [unitId]: { x, y, w, h } }`。竖排布局产物,供无 DOM 布局引擎的 Revideo 定位、供缩略导航器降采样(§7 挂件"缩略导航器")。

### 12.3 几何测量纪律

字级几何**一次性测量并缓存**(仅字体/尺寸变更时重算)。**禁止在动画循环内读取 `getBoundingClientRect`**——长文会触发 layout thrashing。f(t) 与所有挂件(含缩略导航器)只消费缓存,不读真实 DOM。**一份几何,多处消费,零重复测量。**

### 12.4 长文性能纪律(v0.8 新增,风险前置)

楞严咒级长文(约 2600 字 → 叠加 ruby 与包装层约 8000–10000 DOM 节点 + `vertical-rl`)是浏览器排版最少被优化的路径。三条硬纪律:

1. **激活态更新只许改叶子节点**(toggle class / 叶子内联变量);**禁止在容器级改 CSS 变量**——全树 style recalc 是真正杀手,§12.3 只防了 layout read 一半。
2. **视口虚拟化为一等设计,非事后补丁**。离屏单元用字级几何表(§12.2)定位占位,不进 DOM;缩略导航器消费几何表而非真实 DOM。二者与虚拟化天然契合。
3. **Level 1 硬性能指标**:楞严咒全文 + 逐字高亮 + 60fps + 中端手机。过不了此条,后续全部白谈。**这是第一阶段第一个必须先做的真机验证。**

## 13. 主渲染选型

### 13.1 决策:DOM/CSS 优先,Canvas 押后

主渲染走 **DOM/CSS**(字级 `<span>` + CSS 变量 + `writing-mode: vertical-rl`),不走 Canvas。竖排 CJK 浏览器原生;每字一个可寻址 DOM,天然支持 CSS 变量填充与无障碍;自包含 HTML 无引擎依赖。

> **头号风险点(须最先压测)**:**竖排 + 注音(ruby 右侧)是各家浏览器排版支持最不齐处**;梵汉对照(悉昙/罗马转写混入竖排中文)会进一步打断竖排流,楞严咒正好有。**动手做全套模板前,先只拿 20 字做"竖排+右侧注音+逐字高亮"三浏览器真机测试**,过关再铺全文。

### 13.2 引入 Canvas 的分界线

仅当视觉模板需要复杂粒子/光效/矢量变形/自由轨迹动画、DOM 力不从心时,才将 Canvas/WebGL 作为**局部特效层旁挂**。分界线:「文字与结构呈现」DOM ／「自由图形特效」Canvas。

### 13.3 LeaferJS(备查)

MIT、零依赖、70KB、类 DOM API,是旁挂特效层的可选项。风险:竖排 CJK 无文档级支持证据;单作者主导 + 商业插件模式的长期维护风险。不进第一阶段主链路。

## 14. 资源模型

### 14.1 统一机制:asset + 降级阶梯 + 预算选档

每个重资源声明一条**降级阶梯**,导出适配器按**体积预算**沿阶梯选档:

```
audio    → opus_64k 重编码 → poster 静默            (v0.8 新增音频转码档)
video    → poster 静帧      → 纯色/占位
image_hi → image_lo(WebP)  → 占位
font_ext → subset           → 系统字体回退
```

media 不特殊处理,只是阶梯最陡的一种资源。

### 14.2 二进制寻址(源数据纪律)

作品**源数据只存资源引用(URL / 内容寻址),绝不内联 base64**。二进制由资源层管理。**注意:此约束仅针对源数据;导出产物的内联是 §21 导出期变换,合法且必要(§14.5、§21.3)。**

### 14.3 media 时间性契约

media 进度 = 作品 `t` 的纯函数,**不得自带时钟**。片段自然时长 ≠ 时间线区间时,由 `fit` 声明:`stretch`(变速贴合)/ `clip`(原速,末帧冻结)/ `loop`(原速循环)。

### 14.4 media 优先级与形态

**静帧 + 声明式缓慢运动(Ken Burns / 淡入淡出)为动态背景主力**,由 `image` + 效果器(§7.6)表达,不碰 media 二进制。真·视频 media 退为少数特例(法器/仪轨演示)。media 第一阶段优先级低。

### 14.5 体积预算为一等参数

自包含 HTML 导出携带显式**体积目标**,导出器据此自动降档并向作者暴露实时预估。预算档现实化(v0.8 修订):

- **纯文本经文档 <500KB**:无音频,仅正文+注音+字体子集。
- **含音频档 5–20MB**:音频经 Opus 64kbps 重编码(10 分钟 ≈ 4.8MB,人声可接受),作为阶梯一级降档。
- 字体子集化为轻量化第一关,优先级高于 media。**"含音频作品塞进 500KB"是幻觉数字,不设此档。**


## 21. 导出适配器契约

### 21.1 适配器统一接口

所有导出器实现同一契约,**消费 §12 两份共享数据,不得自持渲染逻辑**:

```
ExportAdapter {
  frameState(t): FrameState          // f(作品, t),纯函数
  geometry():    GeometryTable       // 字级几何表(t 无关)
  budget:        SizeBudget          // 体积目标(§14.5)
  pickAssetTier(asset, budget): Tier // 沿降级阶梯选档(§14.1)
  viewerBake:    ViewerIntent | null // 导出时"焊入"的观众态(§12/§21.4)
  emit(): Artifact                   // 产出成品
}
```

### 21.2 三条不可违反的约束

- **单一真源**:适配器不重新实现 f(t) 或几何,只调用共享核。
- **时间采样是适配器职责**:HTML 适配器按交互实时求值;视频适配器按帧率离散采样 `t = n/fps`;字幕适配器按锚点区间导出。核心 f(t) 对采样方式无感。
- **资源选档由预算驱动**:据 `budget` 沿阶梯自动降档,向作者暴露实时预估。

### 21.3 HTML 适配器的自包含纪律

自包含 HTML 导出内嵌 f(t) 求值器、flattened token 表与观众控制层(§12),**运行期零外部解析依赖**。二进制资源按 §14.2 走引用、按 §14.5 预算内联/外链择档——**含音频作品必须内联转码音频**,否则"发给朋友打开即播"失效为哑巴经文。

### 21.4 第一阶段导出器清单(v0.8 定序)

| 导出器 | 阶段 | 说明 |
|---|---|---|
| **自包含 HTML** | 一阶段 | 内嵌 f(t)+观众控制层,含转码音频;"做好发朋友打开即播"最轻分享 |
| **字幕 SRT / ASS** | 一阶段 | 时间线+锚点+文本轨→格式转换;ASS `\k` 标签原生支持逐字卡拉OK染色;多注音轨→多语言 CC。**在 Revideo 写完前即为 YouTube 频道产出生产力** |
| **视频(Revideo,MIT)** | 二阶段 | 自托管渲染无限制,原生支持 MCP/AI agent;核心已是数据驱动函数,仅加输出适配器 |
| **可打印静帧(PDF/长图)** | 二阶段 | t 冻结;字级几何表已是排版产物,产出抄经描红帖/经折装/咒轮卡;高自传播实物,"东方文本呈现标准"最硬实证 |

### 21.5 观众态焊入规则

- **HTML**:观众控制层**保活**——观众可变速/调字号/切主题/遮字自测(§12)。
- **视频/字幕**:观众控制层**焊死**——作者导出前选定的 rate/主题被"烤"进帧流。
- 哪些焊入/焊死由适配器裁决,同一开关两种命运,与"开关正交性"铁律一致。

# 第六卷 · 工程契约

## 20. undo/redo

### 20.1 定案:命令流 + 稀疏快照,不做反向操作

作品状态既是纯数据、渲染既是 `f(作品, t)` 纯函数,则"回到上一步" = 把作品数据换回上一版本快照并重跑 f(t),无需任何 renderer 侧逆动画。undo/redo 从"每个编辑动作都要写配对 do/undo"坍缩为"快照切换"。

### 20.2 机制

- 每次编辑产出一条**命令**(声明式 patch)。
- 每 N 条命令或每逢重操作,落一份**完整快照**;两快照间靠重放命令重建。
- undo = 取目标点最近快照 + 正向重放至该点 → 重跑 f(t)。全程无逆操作。
- 重放后字级几何按 §12.3 规则决定是否重测,多数 undo 命中几何缓存。

### 20.3 边界

- 只管作品数据,**不管**播放头 `t`、视口缩放、观众意图(§12)等瞬态状态。
- 快照密度、log 上限属工具层调参。

## 22. 验证与降级的求值时机

### 22.1 三期分层

| 期 | 时机 | 职责 |
|---|---|---|
| **静态验证** | 编辑期 / 保存期 | schema 合规、继承环检测、fragment 相交冲突、多版本共存、悬空引用 |
| **解析期** | §19 管线运行时 | token 悬空、slot 未覆盖、资源引用不可达 |
| **运行期** | f(t) 循环内 | **只做资源降级,不做逻辑校验** |

结构性错误一律前移至静态期硬失败,绝不进运行期。运行期唯一容许的"变通"是资源沿阶梯降级。

### 22.2 优雅降级 ≠ 容错逻辑

- **资源降级(§14)**:重资源缺失/超预算 → 沿阶梯换轻档。确定性、非分支、运行期允许。
- **结构容错**(如"slot 没定义就瞎猜一个"):**禁止**。缺定义 = 静态期报错。

### 22.3 降级的可预测性

同一作品 + 同一预算 → 恒定降级结果(降级是预算的纯函数)。作者可在编辑期预览任一预算档的降级形态。

## 23. 有限交互契约〔正式占位·内容以行动书 v0.1 为准〕

> **要点**(据既往结论):**两基元(移动播放头 seek / 计数器自增 increment)、五动作封闭枚举 + 三条铁律 + 显式白/黑名单**,在不引入状态机、不破坏 `f(t)` 纯函数前提下,支持念珠计数、点击导航等事件驱动作品。
> **无时序场景的"当前遍数"归 increment 管**(与 §2.4 有时序场景的"展开"显式分家)。
> **与 §12.4 遮字自测的边界(待合并时复核)**:遮字"点击现形"当前归为观众端令牌瞬态覆盖(§12.4),绕开状态机。合并行动书时须确认 §23 五动作枚举是否需为"点击现形"留位,或维持"令牌瞬态覆盖"归属。这是全文档唯一悬置的边界钉子,不预先焊死。

# 第七卷 · 挂件与观众端控制

## 挂件清单(第一阶段)

挂件均为 §7.5 契约下的纯函数,订阅激活态,填入槽位:

| 挂件 | 订阅 | 职责 |
|---|---|---|
| **逐字高亮器** | 文本轨激活态 | 当前单元填充/放大;拖腔靠多区间激活态自然处理 |
| **当前句方框** | 句级激活态 | 框出当前诵读句(原图 276 高亮) |
| **遍数计数器** | 重复维展开实例 / §23 increment | 显示 "1234567遍" 进度点 |
| **章节指示器** | 层级激活态 | 显示 "伍 261~280" 当前会/范围 |
| **缩略导航器** | 几何表 + 层级配色 + f(t) | 全篇色块导航(详见下) |
| **区间循环器** | playbackPolicy.loop | A-B 区间反复(学唱/观众端复用) |
| **注音层** | 注音轨(role 筛选) | 贴字注音;显隐/切换受观众端令牌控制 |

**变体用配置区分,不做独立挂件**(§7.5)。

## 缩略导航器契约(v0.8 正式化)

原图底部彩带的正式实现。**核心:不存任何经文图像(不拼长图、不存整卷 SVG 副本),实时读几何表画色块。**

```
MinimapWidget {
  subscribe: ["layout"]                     // 层级+分组配色
  inputs: geometryTable, flattenedTokens, activeState(t)
  render():
    每 unit → 几何表位置等比缩小到导航条尺寸 → 一个微缩块
    每块颜色 ← 该 unit 的会/分组 → color.group.* 令牌取色
    当前激活 unit → 高亮块 + 定位滑窗
    → 输出一组 <rect>(SVG)
}
```

**四条纪律:**

1. **导航栏不显示字,只显示"多长/分几段/什么色/我在哪"** —— 四信息全不需图像。它是主渲染的**降采样镜像**:同批数据画两遍,一遍原尺寸(主经文 DOM),一遍缩到底部(导航 SVG)。经文/主题/进度一变全自动跟随,因为读的就是源头。
2. **渲染用 SVG `<rect>`,非 DOM div、非位图**:楞严咒约 2600 块,2600 个 `<div>` 拖垮页面;一个 `<svg>` 放 2600 个 `<rect>` 轻量、矢量、可点击 seek。**这与"把经文烤成 SVG"是两回事**——前者画抽象色块(活数据实时投影),后者存经文副本(死数据)。落在 §13.2 分界:文字 DOM,纯图形矢量。
3. **必须消费几何表缓存,禁止遍历真实 DOM 取位**(§12.3)——否则滚动/动画触发布局抖动。一份几何,主经文与导航器两处消费。
4. **点击色块 = seek**:走 §23 seek 基元,不引入新交互机制。

## 观众端播放控制契约(§24–§29)

> **补齐 v0.7 唯一一等契约缺口**:"学习者每天翻开来练"这条主干线的控制层,提升到与作者端(§1–§23)同级。
> **一句话哲学**:观众端不是新系统,是既有骨架的**第二个消费者**。作者调"默认长什么样",观众调"此刻我要它长什么样"——同一套令牌、同一套轨道、同一个 f(t),只多一层观众意图。

## 第一原则:观众端不是"一堆开关"

否决"给播放器加几十个散落 UI 状态"的做法。观众端所有控制,本质只两类动作:

1. **换一个令牌分支**(字号↑、切暗色、关注音):与作者"换肤"同机制,只是发起者变观众。
2. **改一个播放器策略参数**(变速、循环、定时、纯音频):f(t) 之外的**采样器**行为,不碰内核、不碰数据。

于是观众端 = 一层薄瞬态覆盖,叠在解析链最末端(§5.4 第四层)。删掉观众意图 = 回到作者默认。**一个新契约,零新机制**——这是内核原则 7"一份数据多消费者"最彻底的兑现。

## 25. 两把尺子

### 25.1 尺子A:视觉偏好 viewerTokens(令牌层观众覆盖)

观众只能碰**作者已声明开放**的令牌。作者授予边界,观众边界内自由。

```json
// 作者端(视觉模板内新增,§5)
"viewerAdjustable": {
  "type.main": { "min": 20, "max": 48, "step": 2, "label": "正文字号" },
  "theme":     { "options": ["light", "dark", "sepia"], "label": "主题" },
  "type.ruby": { "toggle": true, "label": "显示注音" }
}
```

- **自由度由作者授予,非系统默认全开**——同时解决"给观众自由"与"防止拼出错乱版面"两难。作者不想让人放大破版就不开 `type.main`。
- 观众调整存 `viewerTokens`(瞬态,localStorage/URL,**不进作品数据、不进 undo**)。
- 换主题永不崩坏(§5.1 鲁棒性直接继承)。
- **`template.viewerAdjustable` 是本卷唯一需新增的 schema——一字段解锁一整层学习体验。**

### 25.2 尺子B:播放策略 playbackPolicy(采样器行为,不碰数据)

```json
"playbackPolicy": {
  "rate":        { "value": 1.0, "preservePitch": true },
  "loop":        { "kind": "none | region | count", "region": ["a3","a9"], "count": 108 },
  "sleep":       { "fadeOutAt": 1800, "fadeSec": 30 },
  "displayMode": "full | audio-only | text-only",
  "autoScroll":  true
}
```

- 每项都是 f(t) 之上的采样策略,内核零感知。变速=t 轴缩放(§12.1,与主时钟契约一致);循环=采样器区间末回跳(**非 f(t) 内部循环,守住纯函数**);定时=到点对输出叠全局 opacity 包络;displayMode=选择 renderer 消费帧状态哪些字段(f(t) 照产全量帧,渲染层决定显不显)。

## 26. 学习者六大高频能力(逐条落到两把尺子)

| 能力 | 归属 | 机制(复用既有) | 学习场景 |
|---|---|---|---|
| 变速不变调 | 策略B | `rate.preservePitch`,浏览器原生 | 练难句、学拖腔板眼 |
| 注音显隐/切换 | 令牌A | `type.ruby.toggle` + 多注音轨 role 选择 | 初学开拼音,背诵关掉自测 |
| 字号实时调 | 令牌A | `type.main` 授予区间内滑动 | 年长信众视力刚需 |
| 自设循环遍数 | 策略B | `loop.count`(108/无限),复用 §23 计数 | 持咒定课 |
| A-B 区间循环 | 策略B | `loop.region` 绑两锚点,复用区间循环器 | 单句反复跟唱 |
| 睡眠定时+纯音频 | 策略B | `sleep` 包络 + `displayMode:audio-only` | 睡前持诵、后台干活 |

**六项里五项是"授予/选择"而非"新功能"**。真正需新写的只有 §25.1 的授予声明。兑现内核原则 5"现补几近免费"。

## 27. 遮字自测(易背诵版接入观众端)

本卷唯一超出"纯复用"、值得单独发明的能力——佛学背诵杀手级场景,架构几乎免费支持。

- **遮什么**:由易背诵版分组轨(§6)天生提供——按 `group` 遮、按层级遮、全遮留注音。**作者做易背诵版时顺手就喂出自测能力,零额外标注。**分组数据反向成为记忆测试遮罩地图。
- **怎么遮**:令牌层一个 `mask` 状态(把某组 `color.fg` 覆盖为 `color.bg`,字隐进背景);点一下现形=局部清除该单元 mask,是 §5.3 单元精修的瞬态版。
- **不引入状态机**:遮/现形是令牌瞬态覆盖的确定性行为,非 if-else。

```json
"viewerPractice": {
  "mask": { "by": "group | level | all", "reveal": "tap | hover | timed" }
}
```

**意义**:易背诵版在 v0.7 只是"给作者排好背的版面"(输出物);接入观众端后变成"陪学习者主动记忆的工具"(练习闭环)。同一份分组数据,作者端排版、观众端测验。
> **边界钉子**:"点击现形"与 §23 五动作枚举的关系待行动书合并复核(见 §23)。

## 28. 观众端禁区(守住内核不被侵蚀)

- **不改作品数据**:观众意图全为瞬态覆盖,存本地/URL,永不写回 Work、永不进 undo。作者的作品是活数据,观众的调整是"我这次怎么看它",物理隔离。
- **不触碰未授予令牌**:自由度由 §25.1 授予,防错乱版面的责任在作者 min/max,不在运行期兜底。
- **不引入任何条件逻辑**:遮字现形、循环回跳都是确定性覆盖/采样,非分支。§22 铁律对观众端同样成立。
- **纯音频/定时是"输出包络",非新渲染路径**:f(t) 照产全量帧,渲染层决定显不显示。

## 29. 导出继承(与 §21 接口)

- **自包含 HTML**:观众控制层**默认焊入**。发给同修的 HTML 即可变速/调字号/切暗色/遮字自测——学习工具属性随作品传播,"结缘分享"从"看一篇成品"升级为"送一个练习伴侣"。
- **视频/字幕**:观众控制层**焊死**(烤死的时刻流)。作者导出前选定的 rate/主题烤进帧。
- 焊入/焊死由 §21 适配器裁决,同一开关两种命运,与"开关正交性"铁律一致。

# 第十卷 · 阶段路线(统一坐标,替代 v0.7 双轨划分)

废除 v0.7"第一阶段"与行动书"Level 0–4"并存的双坐标,统一为下表。

## Level 0 — 内核骨架(先跑通数据流)

- 骨架 parser(§8)→ 严格 JSON(§1–§4)
- f(t) 求值器 + 帧状态契约(§12.1/12.2)
- 三层解析链 resolve(§5,先不含继承/组合)
- 最小 DOM 渲染:竖排 + 逐字高亮

**Level 0 出口即第一个真机验证(不可跳过)**:楞严咒 20 字(261~280)竖排 + 右侧注音 + 逐字高亮,三浏览器过关(§13.1 头号风险)。

## Level 1 — 最小可用播放器

- 三挂件跑通:逐字高亮器 + 当前句方框 + 遍数计数器
- **挂件契约(§7.5)为本级前置阻塞,先于一切挂件实现**
- 节拍对齐 + 打点对齐(§3.2)两种锚点生成器
- repeat 解析期展开(§2.4)
- 主时钟契约(§0)接入 AudioContext
- **Level 1 硬指标(§12.4)**:楞严咒全文 + 逐字高亮 + 60fps + 中端手机。**不过则停,回炉性能。**

## Level 2 — 完整创作 + 观众端 + 自包含分享

- 完整三层解析链 + 继承(§16)+ 组合(§17)+ pin 版本(§18)
- 缩略导航器 + 章节指示器 + 注音层挂件
- 易背诵版排版轨(§6)
- **观众端控制层(第七卷·观众端控制)**:两把尺子 + 六能力 + 遮字自测
- 转场系统(§7.2,含 enter 入场编排)
- 背景图令牌化(§5.5)
- **自包含 HTML 导出(§21.3,含转码音频)**
- **字幕 SRT/ASS 导出(§21.4)—— 即刻为 YouTube 频道产出生产力**
- undo/redo(§20)+ 三期验证(§22)

## Level 3 — 视频与可打印(二阶段)

- Revideo 视频导出适配器
- 可打印静帧(抄经帖/经折装 PDF)
- 强制对齐(AI 补密集锚点)
- 学唱模式完善(变速+A-B 已在 L2,此级补波形可视化)

## Level 4 — 生态与规模化(二阶段+)

- 多轨时间线可视化工作台(**v0.7 第一阶段已砍出,移至此**)
- AI 内容生成管线(复用命令流,§20)
- 模板社区 registry + 渲染快照 diff 判版本(§18.2)
- 共享连读词典 / ARIA 无障碍契约
- PWA 离线 + 睡眠场景打包

## 关键排序纪律

1. **性能真机验证前置到 Level 0/1 出口**,不押后。
2. **挂件契约先于挂件**,时间线工作台砍出第一阶段(有打点对齐后 L1–L2 不需要它)。
3. **字幕导出排在视频前**——零成本、即刻服务首要输出目标 YouTube。
4. **第一性诉求是"第一个能跑的播放器"**,非规模化;AI 管线服务规模,置后。
